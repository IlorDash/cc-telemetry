# Данные и приватность

На этой странице перечислено, что отправляют клиенты, что сервер хранит и что выбрасывает, где
лежат данные, как перестать отправлять промпты и как удалить сохранённое. Описана работа Claude
Code 2.1.323 с настройками, которые записывает клиентский скрипт.

!!! warning "Данные личные"
    Стек хранит ваши промпты, пути к файлам и e-mail аккаунта. Запускайте его только на
    доверенном ПК и в доверенной сети. Если это рабочие сессии, убедитесь, что работодатель
    разрешает отправлять данные на этот сервер, прежде чем подключать ПК.

---

## Что отправляет Claude Code

| Группа | Что | От чего зависит |
| --- | --- | --- |
| Промпты | Текст ваших промптов (`user_prompt.prompt`) | `OTEL_LOG_USER_PROMPTS=1`, его ставит клиентский скрипт |
| Ответы Claude | Полный текст ответов (`assistant_response.response`) | Тот же переключатель: отдельного нет. Сервер его отбрасывает, см. ниже |
| Параметры инструментов | Пути к файлам, шаблоны поиска и команды Bash. Не содержимое файлов и не вывод инструментов: только его размер в байтах (`tool_result_size_bytes`) | `OTEL_LOG_TOOL_DETAILS=1`, его ставит клиентский скрипт |
| Использование | Модель, токены (включая кэш), стоимость, длительности, время до первого токена, effort, названия субагентов и навыков, решения по разрешениям, время хуков | Всегда |
| Ошибки API | HTTP-статус и текст ошибки неудавшегося запроса | Всегда |
| Метрики | Токены, стоимость, число изменённых строк кода, время активности | Всегда |
| Личность | E-mail аккаунта, ID аккаунта и организации, тариф (`pro`, ...), ID сессий и промптов, версия ОС, а также `host` и `project`, которые клиентский скрипт кладёт в `OTEL_RESOURCE_ATTRIBUTES` | Всегда |

`project`, который показывают дашборды, как таковой не отправляется. Если метки нет, сервер
определяет его по путям файлов в вызовах инструментов и по рабочей папке, которую присылает хук
сессий, см. [Проект](clients.md#проект).

### Хук сессий

Клиентский скрипт также ставит хук, который раз в сессию и при изменениях отправляет на порт
`4318`:

- название сессии и git-ветку;
- первую рабочую папку, в пути которой есть имя пользователя ОС;
- версию Claude Code.

Он читает это из локальных файлов сессий. Ваши промпты и ответы Claude он не читает и не
отправляет. Чтобы убрать его, запустите клиентский скрипт с `-NoSessionMeta` (Windows) или
`--no-session-meta` (Linux), см. [Отмена](clients.md#отмена).

## Что сервер отбрасывает

Коллектор удаляет атрибут `response`, то есть текст ответа Claude, из каждого события логов до
сохранения (`attributes/drop_response` в `otel-collector.yaml`). Дашборды его не используют.
Длина ответа (`response_length`) остаётся. Всё остальное из таблицы выше хранится в том виде, в
каком пришло, без других фильтров.

## Где лежат данные

- **Телеметрия остаётся на ПК с сервером.** Коллектор пишет каждое событие в ClickHouse
  (`otel.otel_logs` и таблицы метрик), а тот хранит его в томе Docker `clickhouse-data`. Других
  экспортёров у коллектора нет: никуда на другие серверы ничего не пересылается.
- **С чем Grafana связывается сама.** Стек не меняет настройки Grafana по умолчанию, поэтому
  Grafana отправляет анонимную статистику использования и проверяет обновления на grafana.com, а
  плагин ClickHouse скачивается с grafana.com при первом запуске. Ваших промптов и событий в этом
  трафике нет. Поэтому серверу нужен интернет при первом запуске, и полностью автономным он не
  является.
- **Доступны из сети, только если вы это разрешили.** На Windows-сервере Grafana опубликована
  только на `localhost`, а порты OTLP открываются для сети только после `-EnableLan`. На
  Linux-сервере все три порта открыты для сети, если не указать `--local-only`. См.
  [страницу сервера](server.md). У OTLP нет аутентификации, а Grafana работает по обычному HTTP:
  открывайте доступ из сети только в доверенной сети.
- **`RETENTION_DAYS` дней.** По умолчанию 365, на Raspberry Pi 4 — 180; более старые строки
  удаляются, см.
  [Место на диске и срок хранения](maintenance.md#место-на-диске-и-срок-хранения). Claude Code
  удаляет свои файлы сессий примерно через 30 дней, а сервер хранит историю дольше.
- **В резервных копиях.** Выгрузка `linux-server-tools/backup.sh` содержит всё это, включая
  промпты, в `backup/`, см. [Резервная копия и
  восстановление](maintenance.md#резервная-копия-и-восстановление).
- **В Grafana.** Каждый, кто может войти в Grafana, видит промпты, пути и e-mail всех
  подключённых ПК. Текст промптов показывается на дашбордах **Сессии** и **Промпты**.

## Запись промптов

Клиентский скрипт всегда ставит `OTEL_LOG_USER_PROMPTS` в `1`. Без него текст промптов не
отправляется: столбцы с промптами в дашбордах пусты или содержат `<REDACTED>`, а остальное
продолжает работать, потому что стоимости, токенам и вызовам инструментов текст не нужен.

| Вы хотите | Сделайте на клиенте |
| --- | --- |
| Перестать отправлять промпты | В `env` файла `settings.json` (`%USERPROFILE%\.claude\settings.json` в Windows, `~/.claude/settings.json` в Linux) поставьте `OTEL_LOG_USER_PROMPTS` в `0` или удалите ключ. Перезапустите сессии Claude Code |
| Отправлять снова | Поставьте `1` и перезапустите сессии |
| Не отправлять ещё и пути с командами | То же самое с `OTEL_LOG_TOOL_DETAILS`. Определение проекта и часть панелей, которым нужны пути к файлам, тогда останутся пустыми |

!!! warning "Клиентский скрипт возвращает значение"
    Скрипт перезаписывает свои ключи при каждом запуске, поэтому после отключения записи
    промптов повторный запуск `setup-client.ps1` или `setup-client.sh` снова ставит
    `OTEL_LOG_USER_PROMPTS` в `1`. После каждого запуска меняйте значение заново. Параметра для
    этого у скрипта нет.

Уже отправленные промпты остаются в хранилище. Отключение переключателя их не удаляет.

## Удаление данных

В репозитории нет команды, которая удаляет часть данных, например одного ПК или одной сессии.
Поддерживается удаление всего с запуском с пустого места.

!!! warning "Это нельзя отменить"
    Если данные могут понадобиться, сначала сделайте копию: `bash linux-server-tools/backup.sh
    dump` (с префиксом `wsl -d Ubuntu --`, если Docker работает в WSL), см. [Резервная копия и восстановление](maintenance.md#резервная-копия-и-восстановление).
    В копии будут те самые промпты, которые вы хотели убрать, поэтому удалите и её, когда она
    станет не нужна.

1. Остановите отправку с клиентов, иначе новые события снова наполнят стек: см.
   [Отмена](clients.md#отмена) и таблицу выше.
2. На сервере в папке `cc-telemetry` удалите стек вместе с томами (с префиксом `wsl -d Ubuntu --`,
   если Docker работает в WSL):

    ```bash
    docker compose down -v
    ```

    Это удаляет `clickhouse-data` и вместе с ним собственную базу Grafana.
3. Снова запустите серверный скрипт. Он поднимет стек с пустыми таблицами и сохранит `.env`.
4. Удалите ненужные папки в `backup/`, в том числе папки `pre-update-*`, которые пишет
   `--update`.

Остановка стека без `-v` ничего не удаляет, см.
[Остановка и удаление стека](maintenance.md#остановка-и-удаление-стека).
