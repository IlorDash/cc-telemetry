# Подключение ПК

Запустите клиентский скрипт на каждом ПК, чьи сессии Claude Code вы хотите видеть, включая
серверный ПК. Скрипт меняет только файлы вашего собственного пользователя и не требует
дополнительных программ: Claude Code экспортирует события сам.

## Перед началом

| Что нужно | Подробности |
| --- | --- |
| Claude Code | Версия **2.1.310 или новее**: в старых версиях события инструментов не содержат `agent_id`. Проверить: `claude --version`, обновить: `claude update` |
| Адрес сервера | LAN-адрес, который вывел серверный скрипт, либо `localhost` на самом серверном ПК |
| Клиентский скрипт | [`client/setup-client.ps1`](https://github.com/IlorDash/cc-telemetry/blob/main/client/setup-client.ps1) (Windows) или [`client/setup-client.sh`](https://github.com/IlorDash/cc-telemetry/blob/main/client/setup-client.sh) (Linux). Это единственный файл, который нужен клиенту: скопируйте его на ПК |
| Windows | Windows PowerShell 5.1, больше ничего |
| Linux | `python3` или `jq` 1.6 и новее. Хуку сессий дополнительно нужны bash 4+, GNU `find` и `curl` или `python3` |
| Сеть | Порты `4317` и `4318` сервера доступны с этого ПК (см. [страницу сервера](server.md)) |

---

## Установка на Windows

1. Скопируйте `setup-client.ps1` на ПК.
2. Запустите его с адресом сервера. `-Project` необязателен: в нём перечисляются папки, которые
   нужно пометить их именем (см. [Проект](#проект)):

    ```powershell
    powershell -ExecutionPolicy Bypass -File .\setup-client.ps1 -ServerIp <server-ip> -Project C:\Projects\ProjA, C:\Projects\ProjB
    ```

3. Прочитайте последние строки. Обе проверки соединения должны сообщить `reachable: True`.
4. Если вы ещё не открывали на этом ПК папку проекта из `-Project`, откройте её в Claude Code
   один раз и подтвердите диалог доверия.
5. Перезапустите работающие сессии Claude Code: в VS Code выполните **Developer: Reload
   Window**; в терминале выйдите и продолжите командой `claude -c`. Настройки читаются при
   старте сессии.
6. Сделайте любой запрос и [проверьте, что события приходят](#проверка-что-события-приходят).

### Параметры для Windows

| Параметр | Что делает |
| --- | --- |
| `-ServerIp <address>` | Адрес сервера. Обязателен; буквы, цифры, `.`, `_`, `-` |
| `-Project <folder>, ...` | Папки, которые нужно явно пометить их именем. Добавить ещё можно позже, запустив скрипт с другими папками |
| `-PcName <name>` | Имя, которое показывается как `host`. По умолчанию имя компьютера; буквы, цифры, `.`, `_`, `-` |
| `-SettingsDir <name>` | Папка настроек проекта, если это не `.claude` |
| `-UserSettings <file>` | Файл пользовательских настроек. По умолчанию `%USERPROFILE%\.claude\settings.json`; папка хука создаётся рядом с ним |
| `-ImportHistory` | Один раз: загрузить название, ветку и папку уже существующих на этом ПК сессий |
| `-NoSessionMeta` | Не устанавливать хук сессий; при повторном запуске удаляет хук и его файлы |
| `-WhatIf` | Показать результат и ничего не записывать |

## Установка на Linux

1. Скопируйте `setup-client.sh` на ПК.
2. Запустите его от обычного пользователя, без `sudo`. Для нескольких папок повторите
   `--project`:

    ```bash
    bash setup-client.sh --server-ip <server-ip> --project ~/projects/ProjA --project ~/projects/ProjB
    ```

3. Прочитайте последние строки. Обе проверки соединения должны сообщить `reachable: True`.
4. Если вы ещё не открывали на этом ПК папки из `--project`, откройте каждую в Claude Code один
   раз и подтвердите диалог доверия.
5. Перезапустите работающие сессии Claude Code: в VS Code выполните **Developer: Reload
   Window**; в терминале выйдите и продолжите командой `claude -c`.
6. Сделайте любой запрос и [проверьте, что события приходят](#проверка-что-события-приходят).

### Параметры для Linux

| Параметр | Что делает |
| --- | --- |
| `--server-ip <addr>` | Адрес сервера. Обязателен; `localhost` на самом серверном ПК |
| `--project <dir>` | Папка, которую нужно явно пометить её именем. Повторяйте для нескольких; добавить ещё можно позже, запустив скрипт снова |
| `--pc-name <name>` | Имя, которое показывается как `host`. По умолчанию `hostname -s`; буквы, цифры, `.`, `_`, `-` |
| `--settings-dir <dir>` | Папка настроек проекта, если это не `.claude` |
| `--user-settings <file>` | Файл пользовательских настроек. По умолчанию `~/.claude/settings.json`; папка хука создаётся рядом с ним |
| `--import-history` | Один раз: загрузить название, ветку и папку уже существующих на этом ПК сессий |
| `--no-session-meta` | Не устанавливать хук сессий; при повторном запуске удаляет хук и его файлы |
| `--dry-run` | Показать результат и ничего не записывать |
| `--help` | Вывести список параметров. `-h` — то же самое |

`--import-history` нельзя сочетать с `--no-session-meta`; то же верно для `-ImportHistory` и
`-NoSessionMeta` на Windows. Скрипт для Linux проверяет все файлы до записи первого, поэтому
неверные входные данные ничего не меняют.

## Что меняет скрипт

| Что | Windows | Linux |
| --- | --- | --- |
| Ключи телеметрии (раздел `env`) | `%USERPROFILE%\.claude\settings.json` | `~/.claude/settings.json` |
| Запись хука сессий (`hooks.UserPromptSubmit`) | тот же файл | тот же файл |
| Скрипт хука и его файл состояния | `%USERPROFILE%\.claude\cc-telemetry\session-meta.ps1` и `session-meta.state.json` | `~/.claude/cc-telemetry/session-meta.sh` и `session-meta.state` |
| Метка проекта | `<project>\.claude\settings.local.json`, только для папок из `-Project` (создаётся, если нет) | `<project>/.claude/settings.local.json`, только для папок из `--project` (создаётся, если нет) |
| Резервная копия | `<file>.bak`, сохраняется перед первым изменением | то же |

Все остальные ключи в этих файлах (разрешения, модель, плагины, другие хуки) остаются как были.
Скрипт проверяет, что результат — корректный JSON; файлы переформатируются с новыми отступами,
содержимое не меняется. За пределами вашего пользователя ничего не затрагивается.

Ключи, которые скрипт записывает в `env`:

| Ключ | Значение |
| --- | --- |
| `CLAUDE_CODE_ENABLE_TELEMETRY` | `1` |
| `OTEL_LOGS_EXPORTER` | `otlp` |
| `OTEL_METRICS_EXPORTER` | `otlp` |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | `grpc` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `http://<server-ip>:4317` |
| `OTEL_LOG_TOOL_DETAILS` | `1` (отправляются пути к файлам, шаблоны поиска и команды Bash) |
| `OTEL_LOG_USER_PROMPTS` | `1` (отправляются ваши промпты) |
| `OTEL_LOGS_EXPORT_INTERVAL` | `2000` |
| `OTEL_RESOURCE_ATTRIBUTES` | `project=unknown,host=<PC name>`; в папке из `-Project`: `project=<folder name in lower case>,host=<PC name>` |

Скрипт можно безопасно запускать повторно: он обновляет свои ключи и свою запись хука на месте и
никогда их не дублирует. Если адрес сервера изменился, запустите скрипт снова с новым адресом.

!!! note "Что отправляется"
    `OTEL_LOG_USER_PROMPTS=1` отправляет ваши промпты. Этот же переключатель заставляет Claude
    Code отправлять и его ответы; сервер отбрасывает текст ответов перед сохранением. Полный
    список собираемых данных вынесен на отдельную страницу.

### Отмена

| Что вы хотите | Что сделать |
| --- | --- |
| Убрать хук сессий | Запустите скрипт снова с `-NoSessionMeta` (Windows) или `--no-session-meta` (Linux). Он удаляет запись `UserPromptSubmit`, скрипт хука и файл состояния, а также папку `cc-telemetry` рядом с `settings.json`, когда она опустеет |
| Остановить телеметрию | Удалите перечисленные выше ключи из `env` в `settings.json` (и `OTEL_RESOURCE_ATTRIBUTES` из `settings.local.json` проекта) либо восстановите `<file>.bak`. Отдельного переключателя в скрипте нет |

!!! note "`-NoSessionMeta` не отключает телеметрию"
    Он убирает только хук: Claude Code продолжает отправлять свою телеметрию. В `<file>.bak`
    лежит файл в том виде, какой он был до первого запуска, поэтому восстановление из него
    откатывает и более поздние изменения этого файла.

## Названия сессий, git-ветка и рабочая папка

В телеметрии Claude Code нет ни названия сессии, ни git-ветки, ни рабочей папки. Они есть только
в локальных файлах сессий (`~/.claude/projects/*/<session>.jsonl`; на Windows
`%USERPROFILE%\.claude\projects`). Поэтому, если вы не отключите это, скрипт добавляет в
пользовательский `settings.json` хук `UserPromptSubmit`. Он работает в фоне (`async`, поэтому не
задерживает ваш промпт), а ваши другие хуки остаются на месте.

На каждый промпт хук отправляет название сессии (название из `/rename`, иначе автоматическое
название Claude Code), git-ветку, первую рабочую папку и версию Claude Code для текущей сессии и
для сессий, изменившихся с прошлого запуска. Данные уходят на `<server-ip>:4318` и только когда
что-то изменилось. Хук никогда не читает и не отправляет промпты и ответы.

| Ситуация | Что происходит |
| --- | --- |
| Новая сессия | Claude Code создаёт название после первого промпта, поэтому оно доходит до сервера со следующим промптом, в любой сессии |
| `/rename` | Подхватывается со следующим промптом |
| Сервер недоступен | После неудачной отправки хук ничего не делает 10 минут, затем пробует снова с теми же сессиями |
| Уже существующие сессии | Claude Code хранит файлы сессий около 30 дней. Один раз запустите скрипт с `-ImportHistory` / `--import-history`, чтобы загрузить название, ветку и папку уже существующих на ПК сессий. Больше из них ничего не отправляется |
| Хук не нужен | Запустите скрипт с `-NoSessionMeta` / `--no-session-meta` |

## Проект

Название проекта в дашбордах определяется на сервере для каждой сессии в таком порядке:

| Порядок | Источник | Результат |
| --- | --- | --- |
| 1 | Явная метка: `project=<name>` из `OTEL_RESOURCE_ATTRIBUTES`, записанная через `-Project` / `--project` | Берётся как есть. Используйте её для проектов, где сессии не касаются файлов (только чат, только MCP), и там, где догадка ошибается |
| 2 | Первая рабочая папка сессии, которую прислал хук | Её папка по тем же правилам, что в следующей строке. Сессии, записанные до хука, получают её после `-ImportHistory` / `--import-history`, пока их файлы сессий ещё существуют |
| 3 | Абсолютные пути к файлам в вызовах инструментов сессии | Имя папки (в нижнем регистре), которое встречается чаще всего; при равенстве — по алфавиту |
| 4 | Ничего из перечисленного | `unknown` |

Как папка берётся из пути: это первый сегмент пути после домашней папки и общих папок-контейнеров
вроде `Documents`, `projects`, `src`, `dev`, `work`, `repos`, `github`.
`C:\Users\me\Documents\Projects\Alpha\a.cpp` и `/home/me/src/alpha/a.cpp` дают `alpha`. Пути в
скрытых папках (`~/.claude`), во временных и системных папках игнорируются. Папка рабочего дерева
`alpha-feature` считается проектом `alpha`, если `alpha` уже известен; это догадка по префиксу
имени, поэтому она может объединить разные проекты с общим префиксом (`my` и `my-app`). Явная
метка `-Project` / `--project` этого избегает.

!!! note "Файлы, прикреплённые через `@`, не учитываются"
    Claude Code подставляет их без вызова инструмента, и в событии нет пути. Сессия, где есть
    только вложения через `@` и нет метки, получит `unknown`.

Проект с нестандартной структурой (папки прямо в `/data/x/y/`) получит имя по первой папке
(`data`): пометьте его через `--project`. Проект вычисляется при каждом запросе, поэтому ранее
записанные сессии тоже его получают.

Записываются только сессии, начатые после настройки. Телеметрия отправляется вживую: прошлые
сессии не загружаются (`-ImportHistory` добавляет только название, ветку и папку к сессиям,
которые сервер уже знает), а события, возникшие при недоступном сервере, отбрасываются после
короткой повторной попытки.

## Проверка, что события приходят

1. Перезапустите сессии Claude Code и сделайте любой запрос.
2. Откройте Grafana (см. [страницу сервера](server.md)) и посмотрите дашборд **Overview**. Через
   5-10 секунд там появится сессия.
3. Проект появляется в выпадающем списке **Project**, когда сессия коснулась файла или её рабочая
   папка дошла через хук; с явной меткой — сразу.

---

## Если что-то не работает

!!! warning "Если что-то не работает"
    Устраните причину и запустите скрипт снова. Повторный запуск безопасен.

    | Сообщение или симптом | Причина | Что делать |
    | --- | --- | --- |
    | Скрипт не запускается (политика выполнения) | Windows блокирует неподписанные скрипты | Запускайте точно как показано, через `powershell -ExecutionPolicy Bypass -File ...` |
    | `server <address>:4317 reachable: False` | Сервер выключен, адрес неверный или порт закрыт на сервере | Проверьте адрес; на сервере запустите его скрипт снова (Windows: с `-EnableLan`; Linux: без `--local-only`) |
    | `server <address>:4318 (session titles) reachable: False` и `Session titles are sent only once port 4318 is reachable (update and re-run the server setup).` | Порт 4318 закрыт; сервер, настроенный до появления хука сессий, открывает только 4317 | Запустите серверный скрипт снова (Windows: `-EnableLan`; Linux: без `--local-only`), затем этот скрипт |
    | `ERROR: --server-ip is required` | Linux: не указан адрес сервера | Передайте `--server-ip <address>` |
    | `ERROR: --server-ip '<value>' must be a host name or IPv4 address` или `ERROR: --pc-name '<value>' may contain only letters, digits, . _ -` | Linux: в значении есть другие символы | Используйте буквы, цифры, `.`, `_`, `-` |
    | `ERROR: python3, or jq 1.6 or newer, is required to edit the JSON settings. Install one (for example: sudo apt install jq) and run again.` | Linux: нет инструмента для правки JSON | Установите `python3` или `jq` |
    | `ERROR: project folder not found: <dir>` | Linux: папки из `--project` не существует. На Windows PowerShell сообщает, что не может найти путь | Исправьте путь |
    | `ERROR: cannot merge into <file> (is it valid JSON?)` | Linux: файл настроек — некорректный JSON или не объект. На Windows PowerShell сообщает об ошибке разбора JSON | Исправьте файл вручную; скрипт его не менял |
    | `ERROR: cannot change the hooks in <file> (unexpected "hooks" layout?)` | Linux: `hooks` или список `UserPromptSubmit` в настройках имеет неожиданный тип. На Windows скрипт останавливается с `"hooks" is not an object` или `hooks.UserPromptSubmit is not an array` | Исправьте `hooks` в файле настроек вручную |
    | `ERROR: <file> is not valid JSON after the update; restore it from <file>.bak` | Linux: запись прошла неправильно | Восстановите файл из `<file>.bak` и сообщите об ошибке |
    | `-ImportHistory cannot be combined with -NoSessionMeta` (Windows), `ERROR: --import-history cannot be combined with --no-session-meta` (Linux) | Переданы оба параметра | Передайте только один из них |
    | `import failed (exit code <n>)` | Windows: импорт истории не удался | Запустите скрипт снова с `-ImportHistory` |
    | `Unknown option: <option>` | Linux: опечатка в параметре | Проверьте таблицу параметров |
    | В Grafana ничего нет | Сессия не перезапущена, Claude Code старше 2.1.310 или папку из `-Project` не открывали с подтверждением доверия | Перезапустите сессию; проверьте `claude --version`; откройте папку в Claude Code один раз и подтвердите диалог доверия |

→ Другие симптомы описаны на странице «Устранение неполадок», а собираемые данные — на странице о
данных. Назад к [серверу](server.md).
