# Обслуживание сервера

Эта страница о том, что делать с работающим сервером: обновить его, проверить, сделать резервную
копию и восстановить данные, изменить настройки, остановить или удалить. Про неполадки — на
странице [«Решение проблем»](troubleshooting.md).

Все команды запускайте в папке `cc-telemetry` на ПК с сервером.

| Ваш сервер | Как запускать команды `docker compose ...` и `bash linux-server-tools/...` |
| --- | --- |
| Linux | Как есть. Добавьте `sudo`, если вы не в группе `docker` |
| Windows, Docker в WSL | Поставьте перед командой `wsl -d Ubuntu --`, из PowerShell (подставьте имя своего дистрибутива, если он не `Ubuntu`) |
| Windows, Docker Desktop | `docker compose ...` работает как есть в PowerShell. Вспомогательные скрипты из `linux-server-tools/` — это bash-скрипты, и здесь они описаны только для Linux и для Docker в WSL |

## Проверка стека

```bash
docker compose ps
```

Все сервисы в состоянии `Up`, а `views-init` — `Exited (0)`. `views-init` — разовое задание,
которое создаёт представления `cc.*`, поэтому оно и не должно работать постоянно.

Логи одного сервиса (`-f` — следить за ними, `--tail 100` — последние строки):

```bash
docker compose logs otel-collector
docker compose logs clickhouse
docker compose logs grafana
docker compose logs views-init
```

Лог коллектора — первое место, куда стоит смотреть, если события не приходят; после запуска в нём
есть строка `Everything is ready`.

Повторный запуск серверного скрипта тоже работает как проверка: он никогда не пересоздаёт `.env` и
не удаляет данные. Он печатает `FAIL` для того, что сломано, и `WARN` для того, что лишь вызывает
подозрение.

Чтобы выполнить SQL без ввода пароля, передайте запрос в `ch.sh`. Пароль берётся из `.env` и не
печатается:

```bash
echo "SELECT event, count() FROM cc.events GROUP BY event" | bash linux-server-tools/ch.sh
```

```powershell
"SELECT event, count() FROM cc.events GROUP BY event" | wsl -d Ubuntu -- bash linux-server-tools/ch.sh
```

## Обновление сервера

Обновление переводит сервер на новую версию этого репозитория. Ваши данные лежат в томе
`clickhouse-data`, и обновление их не удаляет.

### Linux

Запустите в папке `cc-telemetry` с теми параметрами, которыми обычно пользуетесь:

```bash
bash setup-server.sh --update
```

!!! note "В первый раз выполните `git pull` сами"
    Версии скрипта, выпущенные до появления `--update`, этого параметра не знают. Один раз
    выполните `git pull`, дальше пользуйтесь `--update`.

Команда проходит такие шаги и останавливается на первой проблеме:

| Шаг | Что делает | Когда отказывается |
| --- | --- | --- |
| Проверки | Ищет `.env`, задаёт ClickHouse пробный вопрос и проверяет рабочее дерево git | Нет `.env` (папка ещё не настроенный сервер); ClickHouse не отвечает; в отслеживаемых файлах есть локальные изменения (`.env` и `backup/` в git игнорируются и не считаются) |
| Страховочная копия | Записывает каждую таблицу `otel.*` в `backup/pre-update-<дата>-<время>/` и рядом — число строк каждой таблицы. Прежние копии остаются | Свободного места меньше, чем несжатый размер данных (копия столько и занимает); при запасе меньше 1,5 раза выводится предупреждение. Также останавливается, если не удалось создать папку или копия не получилась |
| Код | Выполняет `git pull --ff-only`. Слияния и перебазирования не будет | Pull не удался (ветка разошлась, нет сети): на стеке ничего не изменилось. Без upstream-ветки или без репозитория git — только предупреждение, и скрипт продолжает с файлами как есть |
| Серверный скрипт | Снова запускает `setup-server.sh` из обновлённого файла с вашими остальными параметрами: запускает изменившиеся контейнеры, пересоздаёт представления `cc.*`, повторяет проверки. Если изменились `otel-collector.yaml` или `grafana/provisioning/`, этот сервис перезапускается. Файлы дашбордов Grafana перечитывает сама | Обычные ошибки установки, см. [страницу сервера](server.md#если-что-то-не-работает) |
| Проверка данных | Сравнивает число строк с тем, что было до обновления. В каждой таблице должно быть не меньше строк | В таблице строк стало меньше: баннер `FAIL` с папкой копии, код выхода 1 |

В случае успеха он печатает `update finished, no data lost` с папкой копии и командой отката.
Папки копий за вас не удаляются: старые папки `pre-update-*` удаляйте сами, когда они больше не
нужны. Если Docker работает через `sudo`, файлы копии принадлежат root.

Обновление также публикует порт `4318` и открывает его в брандмауэре на сервере в сети, так что
порт получит и более старый сервер.

!!! warning "Grafana на старом сервере"
    Если в `.env` есть `OTLP_BIND=0.0.0.0`, но нет `GRAFANA_BIND` (его записывала старая версия
    скрипта), обновление публикует на `0.0.0.0` и Grafana и печатает `WARN GRAFANA_BIND was
    missing and OTLP_BIND=0.0.0.0: Grafana is now published on 0.0.0.0, reachable from the LAN
    (it was local-only before) ...`. Чтобы оставить Grafana на этом ПК, задайте `GRAFANA_BIND=127.0.0.1`
    в `.env` и снова запустите `bash setup-server.sh` либо передайте `--local-only`, чтобы
    закрыть и порты OTLP. См. [страницу сервера](server.md#порты-и-доступ-на-linux).

### Windows

В Windows-скрипте нет `--update`. Скачайте новую версию и запустите скрипт ещё раз:

```powershell
git pull
powershell -ExecutionPolicy Bypass -File .\setup-server.ps1
```

Скрипт запускает изменившиеся контейнеры и пересоздаёт представления `cc.*`. Сервис, у которого
изменился подключённый файл настроек, он не перезапускает, поэтому после `git pull`, затронувшего
`otel-collector.yaml` или `grafana/provisioning/`, перезапустите этот сервис сами (с префиксом WSL,
если Docker работает в WSL):

```bash
docker compose restart otel-collector grafana
```

Автоматической страховочной копии в Windows нет. Если она нужна, [сделайте копию
сами](#резервная-копия-и-восстановление) до `git pull`. Чтобы применить только изменение в
`clickhouse/views.sql`, весь скрипт не нужен:

```bash
docker compose run --rm views-init
```

Серверу, настроенному до появления хука сессий, нужно ещё раз выполнить
`setup-server.ps1 -EnableLan`, чтобы открыть порт `4318`.

### Откат

В конце вывода `--update` указан прежний коммит. Чтобы вернуться к нему:

```bash
git checkout <previous commit>
bash setup-server.sh
```

В Windows запускайте `setup-server.ps1` вместо `setup-server.sh`. Данные остаются в томе, поэтому
после отката восстанавливать ничего не нужно. После отката выполните `git checkout main`, чтобы у
следующего `--update` была ветка для pull (на отсоединённом `HEAD` ничего не скачивается).

## Резервная копия и восстановление

`linux-server-tools/backup.sh` выгружает каждую таблицу `otel.*` в файл `<table>.native` в папке
`backup` (формат ClickHouse Native). Представления не выгружаются: они пересоздаются из
`clickhouse/views.sql`.

```bash
bash linux-server-tools/backup.sh dump              # otel.* tables -> backup/<table>.native
bash linux-server-tools/backup.sh restore           # appends rows: use on a fresh, empty stack
bash linux-server-tools/backup.sh restore <table>   # one table only
```

На Windows-сервере с Docker в WSL, из PowerShell:

```powershell
wsl -d Ubuntu -- bash linux-server-tools/backup.sh dump
```

`BACKUP_DIR=<папка>` перед командой выбирает другую папку для выгрузки и восстановления.
Относительный путь отсчитывается от папки `cc-telemetry`, а не от текущей папки:

```bash
BACKUP_DIR=backup/pre-update-<date>-<time> bash linux-server-tools/backup.sh restore otel_logs
```

Если Docker требует `sudo`, после него переменная теряется. Передайте её через `env`:

```bash
sudo env BACKUP_DIR=backup/pre-update-<date>-<time> bash linux-server-tools/backup.sh restore
```

!!! warning "Восстановление добавляет строки"
    `restore` дописывает выгруженные строки к тем, что уже есть в таблице. Запускайте его только
    для таблиц, которые сейчас пусты, например на новом стеке после `setup-server.*`. В таблице,
    где строки уже есть, получатся дубликаты. Сначала сверьте число строк.

!!! warning "В копии лежат ваши промпты"
    `backup/` исключена из git, потому что в выгрузке есть всё, что хранит стек, в том числе
    промпты. Храните её там же, где храните другие личные файлы. При Docker в WSL данные лежат
    внутри дистрибутива: `wsl --unregister` их удаляет, поэтому сначала сделайте копию.

Выгрузка в формате Native, поэтому она не привязана к тому. Чтобы перенести данные на сервер с
другой версией ClickHouse, восстановите их в новый стек и сверьте число строк каждой таблицы.

## Пересоздание представлений

Представления `cc.*` обычные: они ничего не хранят и вычисляются при каждом запросе. Поэтому
правка `clickhouse/views.sql` меняет то, что показывают дашборды, за всю историю, а не только для
новых событий. Примените файл так:

```bash
docker compose run --rm views-init
```

Команда ждёт, пока коллектор создаст `otel.otel_logs`, и пересоздаёт представления. То же делает
запуск `setup-server.sh` или `setup-server.ps1`.

## Место на диске и срок хранения

Срока хранения в стеке нет: коллектор создаёт таблицы без TTL, и ничто не удаляет строки. События
лежат в томе `clickhouse-data`, пока вы не удалите их сами. Claude Code удаляет свои локальные
файлы сессий примерно через 30 дней, поэтому сервер хранит вашу историю дольше, чем ПК.

Сколько места занимают данные:

```bash
echo "SELECT table, formatReadableSize(sum(bytes_on_disk)) AS size, sum(rows) AS rows FROM system.parts WHERE database = 'otel' AND active GROUP BY table" | bash linux-server-tools/ch.sh
```

Об удалении данных — на странице [«Данные и приватность»](data.md#удаление-данных).

## Изменение настроек

| Вы хотите | Сделайте так |
| --- | --- |
| Другой порт Grafana (Linux) | `bash setup-server.sh --grafana-port 3001`. Порт сохраняется как `GRAFANA_PORT` в `.env` |
| Другой порт Grafana (Windows) | Не поддерживается: скрипт проверяет и печатает только порт `3000` |
| Другие порты OTLP | Не поддерживается: `4317` и `4318` зафиксированы |
| Оставить сервер только на этом ПК или открыть его для сети (Linux) | `bash setup-server.sh --local-only` или `--lan`. Чтобы изменить только Grafana, задайте `GRAFANA_BIND` в `.env` (`127.0.0.1` или `0.0.0.0`) и снова запустите скрипт: он сохранит значение. См. [страницу сервера](server.md#порты-и-доступ-на-linux) |
| Открыть сервер для сети (Windows) | `setup-server.ps1 -EnableLan` |
| Другая версия ClickHouse (Linux) | `bash setup-server.sh --clickhouse-version <tag>`. Том данных, записанный более новым ClickHouse, со старым не запускается |
| Сменить пароль администратора Grafana | Для этого в репозитории нет параметра. Grafana читает `GRAFANA_ADMIN_PASSWORD` из `.env` при создании своей базы при первом запуске, поэтому правка `.env` позже пароль не меняет. Смените его в самой Grafana (ваш профиль) или сбросьте командой `grafana cli admin reset-admin-password` внутри контейнера grafana |
| Сменить пароль ClickHouse | Для этого в репозитории нет параметра. `CLICKHOUSE_PASSWORD` из `.env` применяется только при первом создании тома ClickHouse, а коллектор, Grafana и `ch.sh` читают его из `.env`. Если сменить его позже, соединение сломается |

## Остановка и удаление стека

| Вы хотите | Команда | Ваши данные |
| --- | --- | --- |
| Остановить стек | `docker compose stop` | Сохраняются |
| Запустить снова | `docker compose up -d` или серверный скрипт | Сохраняются |
| Остановить и удалить контейнеры | `docker compose down` | Остаются в томах `clickhouse-data` и `grafana-data` |
| Удалить всё, включая данные | `docker compose down -v` | **Удаляются** |

!!! warning "`down -v` удаляет все собранные данные"
    `-v` удаляет тома, а вместе с ними все события, которые сохранил стек, и собственную базу
    Grafana. Отменить это нельзя. Сначала сделайте копию (см. [Резервная копия и
    восстановление](#резервная-копия-и-восстановление)) и убедитесь, что она не пустая. Обычный
    `docker compose down` безопасен.

На Windows-сервере с Docker в WSL данные удаляет и `wsl --unregister <дистрибутив>`.

Остановка стека не отменяет того, что настроил Windows-скрипт. Уберите это сами, когда оно
больше не нужно:

| Что | Как убрать |
| --- | --- |
| Keepalive (только WSL) | Удалите `cc-telemetry-keepalive.vbs` из папки автозагрузки; процесс завершится при следующем выходе из системы или перезагрузке |
| Правила брандмауэра и переадресации портов (`-EnableLan`) | Правила `OTLP 4317 (Claude Code telemetry)` и `OTLP 4318 (Claude Code telemetry)` и переадресации `netsh interface portproxy` для обоих портов. Нужны права администратора |
| Правила брандмауэра в Linux | `ufw delete allow <port>/tcp` или `firewall-cmd --remove-port=<port>/tcp` |

Клиенты продолжают слать данные на сервер, пока вы не [отмените их настройки](clients.md#отмена).
